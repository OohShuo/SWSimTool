# SW2MuJoCo 2.0 验证记录

环境：SolidWorks Premium 2025 SP1.2、Windows x64、Python 3.12、MuJoCo 3.14.0。本轮只操作工作区内新建的 `isolated_fixture.SLDASM` 和两个新建零件，没有打开或修改已有用户工程。

## 已通过

- Visual Studio MSBuild x64 构建；Inno Setup 完整安装包构建和本机升级，安装 DLL 与构建 DLL 的 SHA256 相同。
- Python 后端 33 项测试，包括 Blender、PyMeshLab、fast-simplification 三种减面方式；验证超限才减面、原文件不变、失败保留旧输出、最终产物布局、可选附加配置、无归属文件保护和旧受管理网格清理。
- WinForms 模拟 CAD 回归 18 项：碰撞配置按 link 切换、空 link 清空、无效数字阻止错误切换、草稿隔离；仿真附着点按 link 过滤、执行器 joint 归属、motor 隐藏增益、position 显示 kp。
- 真实新建装配：旧 URDF 与仿真属性读取不迁移；明确保存后合并为一个节点；保留其他 Configuration 的旧共享 URDF 树和各自仿真数据；保存树不覆盖碰撞数据；保存并重新打开后数据保留。
- 真实工程导出：普通 URDF 无 `.sim.json`，不受未完成仿真草稿阻碍；可选附加配置可导出；工程 MJCF 从临时 URDF 自动转换，site 按导出的机器人坐标求值；MuJoCo 编译成功，最终目录只有 XML 和 meshes，临时目录清理。
- 安装后原生菜单显示 URDF 配置、碰撞配置、仿真配置、导出与预览，导出菜单区分工程与本地来源；未保留旧 Export as URDF 入口。
- 安装后左侧仿真页添加 frame、拾取新建装配的 Origin_global、更新预览、保存到统一属性节点、绿色确认退出，随后正常关闭 SW 测试实例。
- 新建碰撞测试装配中四种临时简单几何体预览，预览前后装配质量不变。

## 验证范围与异常记录

首次外部测试宿主调用 CommandManager.Activate 失败，不能作为菜单验证证据；后续使用安装 DLL 正常加载插件，在原生菜单中验证入口。

第一轮 UI 自动化通过 set_value 修改下拉框文本后按 Enter，测试实例停止响应并被清理。第二轮通过正常下拉选择、拾取、保存和绿色确认完整通过，退出正常。尚不能认定第一轮停止响应的根因已排除；不能把文字设值等同于实际选中下拉项。

完整交互只在新建小型装配中验证；没有对用户大型工程、真实闭链动力学或每种传感器布局作桌面验证。已有后端约束、执行器和传感器转换测试通过，不等于具体机器人动态稳定性验证。

内部 DLL/COM 标识、安装目录和旧属性识别名保留，以支持升级；产品名称和入口为 SW2MuJoCo。新输出目录符合纯 XML + STL 布局；旧版输出中无法认定归属的 URDF、JSON 或用户文件不会自动删除。

原始测试日志在工作区 build 下：sw2mujoco-backend-tests.log、sw2mujoco-ui-tests.log、sw2mujoco-cad.log、sw2mujoco-final-fixture.log、sw2mujoco-install-final.log。测试脚本在 scripts 下，CAD 脚本要求测试路径和进程标记匹配。
