# SW2MuJoCo 增量 V1 自动化验收（2026-10-07）

后续补充：同日已用全新 SolidWorks 测试装配完成原生增量计数、清缓存全量对照及动力学验证。见 [C# 迁移进度与原生验收](SW2MuJoCo_CSharp迁移进度_20261007.md)。下文保留最初分层自动化验收的范围与记录。

## 结论与范围

自动化验收通过：96 项 Python 后端测试、125 项模拟 SolidWorks / UI 检查，以及 5 组严格 timestep 增量场景。

这是分层验证，不是原生 SolidWorks 端到端实测：C# 使用模拟文档和预置 raw source cache；Python 使用合成 URDF/STL、真实减面后端及本地 MuJoCo 3.14.0。未打开、使用或修改用户现有 SolidWorks 工程。因此原生 SW 从首次完整导出到增量导出的联合计数仍需用新建测试装配验证。

## 严格验收条件

每组 Python 场景首次完整转换时，solver 已启用，timestep=0.001，且确实执行过减面。随后只将 timestep 改为 0.002，其他配置保持相同。

| 场景 | mesh preparation | mesh simplification | MJCF generation | MuJoCo validation | base generation |
| --- | ---: | ---: | ---: | ---: | ---: |
| site | 0 | 0 | 1 | 1 | 0 |
| 恒力 | 0 | 0 | 1 | 1 | 0 |
| 弹簧 | 0 | 0 | 1 | 1 | 0 |
| equality / connect | 0 | 0 | 1 | 1 | 0 |
| 以上组合 | 0 | 0 | 1 | 1 | 0 |

增量步骤同时禁止调用 mesh preparation 和 simplification：如果意外调用，测试立即失败。C# 模拟 ProjectExport 另行检查 GeometryQueries、StlExports 和 SourceBuildCount 均无增加，并验证最新 timestep 已覆盖到导出配置。

## 清缓存后的全量对照

每组场景删除测试临时目录中的新缓存和旧 mesh cache，再执行全量转换。删除前检查缓存路径确实位于该测试临时目录内，不清理用户缓存。

全量步骤断言 base generation=1、mesh preparation>0、mesh simplification>0，避免误将另一次缓存命中当作全量结果。

对照项目包括：

- 编译后的 body、joint、geom、mesh、site、actuator、sensor、equality、tendon 数量和名称。
- 位姿、质量惯量、关节阻尼/附加惯量、接触参数、约束参数、弹簧参数和 solver 设置。
- 三组初始位置/速度下的 mj_forward 结果，包括 site 世界位姿、tendon 长度/速度、被动力、执行器力、约束力和传感器值。
- 每组状态推进 10 步后的 qpos/qvel，检查数值有限且一致。
- 额外比较规范化 XML；语义比较不是仅依赖 XML 字符串。

全部通过。此项证明当前同一生成器的缓存路径与清缓存路径一致，不替代未来直接 MJCF writer 对旧生成器的独立验证，也不证明任意模型长期仿真稳定。
